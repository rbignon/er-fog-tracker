## Overview

The Fog Gate Randomizer tracker mod needs to:

1. **Detect teleportations** - Identify when the player traverses a fog gate, waygate, coffin, etc.
2. **Match to zone links** - Correlate runtime events (entity IDs) with the spoiler log's zone connections
3. **Track inventory** - Read Great Runes and Messmer's Kindling for progress tracking

### Key Data Sources

| Source | Location | Contents |
|--------|----------|----------|
| **Spoiler Log** | Generated by FogMod | Human-readable randomized connections (no entity IDs) |
| **fog.txt** | `fog/eldendata/Base/fog.txt` | Zone definitions, vanilla entity IDs, warp descriptions |
| **fogevents.txt** | `fog/eldendata/Base/fogevents.txt` | Event templates (fogwarp, etc.) |
| **EMEVD files** | `fog/extracted_events/*.txt` | Event scripts with fog gate logic (seed-specific) |
| **MSB files** | Game mod folder | Map data, spawn point positions (not parseable - format unsupported) |
| **Game Memory** | Runtime | Player state, animations, SpEffects, warp requests |

### Spoiler Log Format

Generated by FogMod at runtime (e.g., `spoiler_logs/2025-12-18_19.33.41_log_709745613_97790.txt`):

```
Chapel of Anticipation (scaling: tier 1, previously 6)
Farum Azula - Dragon Temple Lift (scaling: tier 1, previously 14)
  Random: Chapel of Anticipation (before Grafted Scion's arena) --> Farum Azula - Dragon Temple Lift (down the elevator from Dragon Temple Lift grace)
```

Key info: source zone, destination zone, source_details, target_details. **No entity IDs.**

### fog.txt Structure

Contains three main definition types:

1. **Area definitions** - Zones with maps, tags, scaling tiers
2. **Entrance definitions** - Fog gates with vanilla entity IDs
3. **Warp definitions** - ASide/BSide with action and arrival descriptions

Example:
```yaml
- Name: chapel_start
  Text: Chapel of Anticipation
  Maps: m10_01_00_00
  Tags: start
  To:
  - Area: limgrave
    Text: defeating any major boss
    Tags: crawlonly openonly
```

### fogevents.txt Templates

Event templates before seed-specific instantiation. Example fogwarp event (ID 9005777):

```yaml
- RotateCharacter(10000, X36_4, 60060, false)   # Rotate towards X36_4
- WaitFixedTimeSeconds(1)                        # 1 second delay
- ShowTextOnLoadingScreen(Disabled)
- WarpPlayer(X12_1, X13_1, X14_1, X15_1, X8_4, 0)  # Warp to entity X8_4
```

Variables (X8_4, X36_4, etc.) are replaced with actual entity IDs during seed generation.

## Memory Structures

### Pointer Chains Overview

```
WorldChrMan ──────────────────────────────┐
  └─[+0x1E508]→ PlayerIns                 │ (v1.07+, was 0x18468 before v1.07)
                  ├─[+0x160] tae_queued_use_item (u32)
                  └─[+0x178]→ SpEffectCtrl
                                └─[+0x8]→ SpEffect linked list

GameMan ──────────────────────────────────┤
  ├─[+0x10]  warp_requested (bool)        │
  ├─[+0x3C]  initial_area_entity_id (u32) │ destination entity ID
  ├─[+0xAB0] last_load_position (vec4)    │
  ├─[+0xAC0] last_load_orientation (vec4) │
  └─[+0xAC8] load_target_block_id (u32)   │ destination map ID

GameDataMan ──────────────────────────────┘
  └─[+0x8]→ PlayerGameData
              ├─[+0xFF]  equipped_great_rune (byte)
              └─[+0x428]→ key_items array
                [+0x430]  key_items_count (u32)
```

### GameMan Structure

Global game manager handling warps and map transitions.

| Offset | Type | Field | Description |
|--------|------|-------|-------------|
| 0x10 | bool | `warp_requested` | True when a warp is in progress |
| 0x3C | u32 | `initial_area_entity_id` | Destination entity ID (set by EMEVD `WarpPlayer`) |
| 0xAB0 | vec4 | `last_load_position` | Player position after warp completes |
| 0xAC0 | vec4 | `last_load_orientation` | Player orientation after warp |
| 0xAC8 | u32 | `load_target_block_id` | Destination map ID (BlockId format) |

**Critical timing**: `initial_area_entity_id` is set by `WarpPlayer`, which executes ~1 second AFTER the fog animation (60060) starts. The mod must capture this value when `warp_requested` becomes true, not when the animation starts.

### BlockId Format (Map IDs)

Map IDs are packed into a u32 bitfield:

```
bits 31-24: area   (m{AA}_XX_YY_ZZ)
bits 23-16: block  (mAA_{XX}_YY_ZZ)
bits 15-8:  region (mAA_XX_{YY}_ZZ)
bits 7-0:   index  (mAA_XX_YY_{ZZ})
```

Example decoding:
- `1291` → `m11_05_00_00` (aa=11, bb=05)
- `18` → `m18_00_00_00`
- Formula: `aa = map_type & 0xFF`, `bb = (map_type >> 8) & 0xFF`

### WorldChrMan Structure

Character manager with player pointer.

| Offset | Type | Field | Notes |
|--------|------|-------|-------|
| 0x1E508 | ptr | `main_player` | PlayerIns pointer (v1.07+) |

Version differences:
- v1.02 - v1.06: offset `0x18468`
- v1.07+: offset `0x1E508`

### PlayerIns (ChrIns) Structure

Character instance structure.

| Offset | Type | Field | Description |
|--------|------|-------|-------------|
| 0x160 | u32 | `tae_queued_use_item` | Item ID being used (for Medal detection) |
| 0x178 | ptr | `speffect_ctrl` | SpEffect controller pointer |

**Important**: During teleport/loading, PlayerIns becomes `0x0` (null). After teleport, it gets a NEW address.

### SpEffect Structure

Linked list of active effects.

```
SpEffectCtrl[+0x8] → First SpEffect node

Each node:
  +0x08 = param_id (u32) - SpEffect ID
  +0x30 = next (ptr) - Next node in list
```

## Teleportation Detection

### Events to Track (Randomized Destinations)

| Type | Animation | Additional Check | Notes |
|------|-----------|------------------|-------|
| **Fog Wall** | `60060` | - | Walk through fog gate |
| **Back to Entrance** | `60460` | - | Ground point after boss |
| **Waygate** | `60490` | - | Hand turns blue |
| **Sending Gate** | `60490` | - | Same animation as waygate |
| **Coffin** | None | `warp_requested` + `dest_entity_id == 0` | Exclusion-based |
| **Medal** | `50340` | `tae_queued_use_item == 0x40000870` | Pureblood Knight's Medal |
| **Post-Boss Warp** | `12020210` | `warp_requested` validation | After defeating boss |
| **Erdtree Burn** | `68110` | - | Burning Erdtree cutscene |

### Events to Track (Position Awareness Only)

| Type | Detection | Notes |
|------|-----------|-------|
| **Fast Travel** | `warp_requested` + `dest_entity_id != 0` + no animation | Menu teleport |

### Events to Ignore

| Type | Detection | Notes |
|------|-----------|-------|
| **Death** | Animation `4xxx` or `20xxx` | Respawn at grace/stake |
| **Memory of Grace** | Animation `50230` + SpEffect `3226` | Not randomized |
| **Trap Chest** | Disabled in randomizer | N/A |

### Detection Algorithm

```
1. If animation 60060 → FOG WALL
2. If animation 60460 → BACK TO ENTRANCE
3. If animation 60490 → WAYGATE / SENDING GATE
4. If animation 50340 + tae_queued_use_item == 0x40000870 → MEDAL
5. If animation 12020210 + warp_requested was true → POST-BOSS WARP
6. If animation 68110 → ERDTREE BURN
7. If warp_requested + no animation + dest_entity_id == 0 → COFFIN
8. If warp_requested + no animation + dest_entity_id != 0 → FAST TRAVEL
9. If animation 4xxx/20xxx → DEATH (ignore)
10. If animation 50230 + SpEffect 3226 → MEMORY OF GRACE (ignore)
```

### Cutscene Animation Validation

Animations in the `12xxxxxx` range can trigger without an actual warp (cutscenes, visual transitions). These require `warp_requested` validation - they're only valid if `warp_requested` was true during the sequence.

Other animations (FOG, WAYGATE, etc.) don't need this validation.

## Entity and Zone Matching

### The Matching Problem

When the mod detects a fog gate traversal, it sends `(source_map, source_position, destination_entity_id)` to the server. The server must match this to the spoiler log's zone connections.

**Challenge**: The spoiler log contains zone names and descriptions, but no entity IDs:
```json
{
  "source": "Ashen Leyndell - South of Erdtree Sanctuary",
  "destination": "Stranded Graveyard",
  "source_details": "at the side entrance to Gideon's arena from the branches",
  "target_details": "at the exit to Limgrave"
}
```

Multiple fog gates can connect the same map pair (e.g., 3 different warps from m18 to m11_05).

### Entity ID Ranges

| Range | Purpose |
|-------|---------|
| 755890000-755899999 | FogMod spawn points and fog gates |
| 755894xxx | Evergaol entries (subset) |
| 10xxxxxx, 11xxxxxx | Vanilla entity IDs |

### FogMod Entity ID Assignment

From decompiled FogMod source:
- `GameDataWriter.cs` (Dark Souls 3): `int mk = 1815800`
- `GameDataWriter3.cs` (Dark Souls 3?): `int mk = 4105800`
- `GameDataWriterE.cs` (Elden Ring): Decompilation failed (file nearly empty)

Entity IDs are assigned sequentially with `mk++`. Without the Elden Ring starting value (likely 755890000), we cannot predict the exact mapping from code.

### EMEVD Event Structure

A typical fogwarp event extracts:
- `source_entity`: Fog gate to interact with
- `rotate_entity`: Entity to rotate towards
- `dest_entity`: Destination spawn point
- `dest_map`: Destination map (BlockId format)

Example from `m18_00_00_00.txt`:
```
IF Action Button in Area(5, 10000, 755890311)    ← source_entity
...
Rotate Character(10000, 755890310, 60060, 0)     ← rotate_entity
...
Warp Player(1291, 755890092, 0)                  ← dest_map=1291 (m11_05), dest_entity=755890092
```

### Matching Algorithm

The solution cross-references EMEVD events with the spoiler log:

1. **Extract EMEVD events**: Parse all fog warp events to get `(source_map, dest_map, dest_entity_id)`
2. **Parse spoiler log**: Load both `random` and `preexisting` entries as `(source_zone, dest_zone, details)`
3. **Map zones to maps**: Use fog.txt to convert zone names to map IDs
4. **Match by map pairs**: Find zone links where maps align (considering bidirectional gates)

### Traversal Direction

The spoiler lists connections in one direction, but EMEVD events exist for both directions:

- `forward`: Player went source → destination (as spoiler lists)
- `reverse`: Player went destination → source (opposite direction)

### Match Results (Typical Seed)

| Category | Count | Notes |
|----------|-------|-------|
| EMEVD fog warps | ~350 | Total events |
| Spoiler entries | ~260 | 166 random + 94 preexisting |
| Matched | ~200 (56%) | Identifiable zone links |
| Unmatched | ~150 (44%) | Expected - exits, non-fog connections |

**Unmatched warps are expected**:
1. Exits to overworld zones (not tracked in spoiler)
2. Preexisting connections without fog gates
3. Special warps (elevators, dropdowns)

### Output Format

```json
{
  "755890092": {
    "source": "Ashen Leyndell - South of Erdtree Sanctuary",
    "destination": "Stranded Graveyard",
    "source_details": "at the side entrance to Gideon's arena from the branches",
    "target_details": "at the exit to Limgrave",
    "is_one_way": false,
    "type": "random",
    "warp_source_map": "m18_00_00_00",
    "warp_dest_map": "m11_05_00_00",
    "traversal_direction": "reverse"
  }
}
```

## Inventory System

### Item ID Format

Items use a 32-bit `ItemId` with bitfield structure:

| Bits | Field | Description |
|------|-------|-------------|
| 28-31 | category | Item category (4 bits) |
| 0-27 | param_id | Parameter ID (28 bits) |

**Categories**:
| Value | Category |
|-------|----------|
| 0 | Weapon |
| 1 | Protector (Armor) |
| 2 | Accessory (Talisman) |
| 4 | Goods (Consumables, Key Items) |
| 8 | Gem (Ashes of War) |

Great Runes and Kindling are **Goods** (category 4): `0x4xxxxxxx`

### Key Item IDs

| Item | param_id | Full item_id |
|------|----------|--------------|
| Pureblood Knight's Medal | 2160 | 0x40000870 |
| Memory of Grace | 115 | 0x40000073 |
| Messmer's Kindling | 2008021 | 0x401EA3D5 |

### Great Rune Item IDs

| Item | param_id | item_id |
|------|----------|---------|
| Godrick's Great Rune (restored) | 191 | 0x400000BF |
| Radahn's Great Rune (restored) | 192 | 0x400000C0 |
| Morgott's Great Rune (restored) | 193 | 0x400000C1 |
| Rykard's Great Rune (restored) | 194 | 0x400000C2 |
| Mohg's Great Rune (restored) | 195 | 0x400000C3 |
| Malenia's Great Rune (restored) | 196 | 0x400000C4 |
| Great Rune of the Unborn | 10080 | 0x40002760 |

**Unrestored versions** (same rune, different state):
| Item | param_id | item_id |
|------|----------|---------|
| Godrick's (unrestored) | 8148 | 0x40001FD4 |
| Radahn's (unrestored) | 8149 | 0x40001FD5 |
| Morgott's (unrestored) | 8150 | 0x40001FD6 |
| Rykard's (unrestored) | 8151 | 0x40001FD7 |
| Mohg's (unrestored) | 8152 | 0x40001FD8 |
| Malenia's (unrestored) | 8153 | 0x40001FD9 |

**Normalization**: `(param_id - 8148) + 191` converts unrestored to restored param_id for deduplication.

**Note**: Miquella's Great Rune (param_id 2008000) is a DLC story item, not counted.

### Inventory Memory Structure

Key items are stored in the `key_items` inventory array:

```
GameDataMan
  └→ +0x8 → PlayerGameData
              └→ +0x2B0 → EquipGameData (embedded)
                            └→ +0x158 → EquipInventoryData (embedded)
                                          └→ +0x8 → InventoryItemsData (embedded)
                                                      ├→ +0x18 → key_items_head (ptr)
                                                      └→ +0x20   key_items_count (u32)
```

**Flattened offsets from PlayerGameData**:
- `key_items_head`: +0x428 (pointer to array)
- `key_items_count`: +0x430 (u32)

### Inventory Entry Structure (0x18 bytes)

| Offset | Type | Field | Description |
|--------|------|-------|-------------|
| 0x00 | u32 | gaitem_handle | Handle to extended data |
| 0x04 | i32 | item_id | Category (28-31) + param_id (0-27) |
| 0x08 | u32 | quantity | Count owned |
| 0x0C | u32 | sort_id | Acquisition order |
| 0x10 | u8 | unk10 | Unknown |
| 0x14 | i32 | pot_group | Pot group ID (-1 if not pot) |

### Reading Algorithm

```rust
let player_game_data = read_ptr(game_data_man + 0x8);
let key_items_head = read_ptr(player_game_data + 0x428);
let key_items_count = read_u32(player_game_data + 0x430);

let mut great_runes: HashSet<u32> = HashSet::new();
let mut kindling_count: u32 = 0;

for i in 0..key_items_count {
    let entry_addr = key_items_head + i * 0x18;
    let item_id = read_i32(entry_addr + 0x04);
    let quantity = read_u32(entry_addr + 0x08);

    let category = ((item_id >> 28) & 0xF) as u8;
    let param_id = item_id & 0x0FFFFFFF;

    if category != 4 { continue; } // Not Goods

    // Normalize Great Runes
    let normalized = match param_id {
        191..=196 => param_id,                // Restored
        8148..=8153 => param_id - 8148 + 191, // Unrestored → normalized
        10080 => 10080,                       // Great Rune of the Unborn
        _ => 0,
    };
    if normalized != 0 { great_runes.insert(normalized); }

    // Kindling
    if param_id == 2008021 { kindling_count += quantity; }
}
```

### Equipped Great Rune

Direct read: `GameDataMan → +0x8 → +0xFF` (byte value = equipped rune index)

## Implementation Notes

### TeleportType Enum

```rust
pub enum TeleportType {
    FogWall,        // animation 60060
    BackToEntrance, // animation 60460
    Waygate,        // animation 60490 (includes sending gates)
    Medal,          // animation 50340 + item ID check
    Coffin,         // exclusion: warp_requested + no anim + dest_entity == 0
    PostBossWarp,   // animation 12020210 + warp_requested validation
    ErdtreeBurn,    // animation 68110
    FastTravel,     // warp_requested without other events
}
```

### GameManReader

```rust
pub struct WarpInfo {
    pub warp_requested: bool,
    pub destination_entity_id: u32,
    pub destination_map_id: u32,
}

impl GameManReader {
    pub fn is_warp_requested(&self) -> bool;
    pub fn get_destination_entity_id(&self) -> u32;
    pub fn get_destination_map_id(&self) -> u32;
    pub fn get_warp_info(&self) -> Option<WarpInfo>;
}
```

### Key Fix: Destination Entity Timing

**Problem**: Reading `destination_entity_id` when fog animation starts returns 0 (WarpPlayer hasn't executed yet).

**Solution**: Capture when `warp_requested` becomes true:

```rust
if warp_requested && !self.was_warp_requested {
    let current_dest = self.game_man_reader.get_destination_entity_id();
    if let Some(ref mut pending) = self.pending_fog {
        if pending.destination_entity_id == 0 && current_dest != 0 {
            pending.destination_entity_id = current_dest;
        }
    }
}
```

### fog.txt Parsing Gotcha

The parser must check indentation - only parse `Text:` and `Maps:` at root level (2 spaces), not nested fields inside `To:` sections that can have the same field names.
